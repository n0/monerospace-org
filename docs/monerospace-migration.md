# MoneroSpace → XMR Taxi migration

The compact announcement above MoneroSpace's navbar opens the same supported page on `https://xmr.tx.taxi`. The destination acknowledges the shared team and offers a reversible, explicit default preference. Unsupported routes link to the dashboard; no API or server redirects are added.

`frontend/src/resources/monerospace-migration.js` owns the browser flow. `frontend/generate-config.js` embeds it into generated HTML before Angular initialization, with a `source` or `target` role from `index.mempool.html`. It adds no blocking script request or external analytics dependency. `sync-xmr-resources.js` includes its source asset. The source and target copies are identical.

Same-page links retain the allowlisted route, query, and fragment. A bounded fragment envelope carries a ten-minute timestamp, random nonce, original fragment (up to 2,048 characters), and optional language/fiat/timezone preferences. The target removes the envelope before the application boots and validates the preferences against supported language/timezone values and a three-letter currency code. No lookup identifiers are sent to analytics. The fragment is never sent in an HTTP request.

The default preference lives in MoneroSpace's own localStorage, not a cross-site iframe. Clicking “Use XMR Taxi by default” returns through MoneroSpace. A recent source-tab nonce permits the explicitly requested preference to be saved; a missing or expired nonce requires a visible confirmation button on MoneroSpace. The browser then returns to the same native page. “Back to MoneroSpace” removes the default and stays on the same source page. Storage-disabled browsers retain ordinary links and receive a clear message when a preference cannot be saved.

Anonymous counters use `POST /api/v1/migration-events` with exactly `{event}`. Allowed events: `announcement_view`, `try_click`, `arrival`, `default_enabled`, `default_disabled`, `return_visit`, `auto_forward`. The frontend and server honor DNT/GPC. The server validates same-site Origin/Host, caps request size and aggregate rate, and persists daily totals for 90 days without IDs, paths, referrers, user agents, IPs or cookies. The endpoint's nginx access and ordinary error logs are disabled. These are event totals, not unique users or a user-level retention cohort. `return_visit` counts at most one returning browser-day after the arrival day, deduplicated with a local date, without emitting a browser identifier. New preferences selected while trying XMR Taxi are retained through opt-in and later automatic forwarding.

Metrics persist at `/data/migration/migration-events.json` in production, overrideable with `XMR_MIGRATION_METRICS_DIR`. MoneroSpace already mounts `/data`; XMR has a dedicated `/data/migration` volume, separate from provider state. There is no public metrics-report endpoint. Operators can read that JSON file inside the application container.

Local review uses ports 4381 (source) and 4382 (target), only on loopback. Run in each frontend: `node generate-themes.js && node generate-config.js`, then `node node_modules/@angular/cli/bin/ng.js serve --configuration local --host 127.0.0.1 --port 4381 --proxy-config proxy.migration.cjs` (4382 on target). The ignored local proxy points API requests to the existing native explorer. Browser checks stub the metrics endpoint so test activity does not affect public counters.

Verification covers desktop/mobile exact entity/query/fragment transfer, locale and preferences before bootstrap, default forwarding and undo across reloads, unknown nonce confirmation, disabled browser storage, GPC, and real backend HTTP input/privacy/persistence/rate behavior. Browser evidence is in `review/migration/` in the isolated MoneroSpace worktree.
