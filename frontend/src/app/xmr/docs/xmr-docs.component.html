FAQ

What is xmr-space?

A block & mempool explorer for Monero, forked from mempool.space. It surfaces what the Monero chain alone proves and never claims to know more than that.

What is a mempool?

The set of transactions a node knows about that haven't been confirmed in a block yet. Each Monero node maintains its own; ours is whatever monerod's get_transaction_pool returns at poll time.

Why are tx amounts shown as hidden?

Because they are hidden. Monero uses RingCT (Ring Confidential Transactions); the on-chain value of every tx output is a Pedersen commitment that only the recipient (with their view key) and the sender (with the per-tx secret key or a generated tx_proof) can decrypt. xmr-space surfaces only what the chain proves to everyone.

What's the ring size?

Sixteen, since the August 2022 hard fork. Every input is signed against a ring of 16 outputs (1 real + 15 decoys) chosen from the chain's history. Older txs may have ring size 11, 7, 5, or 3. xmr-space flags inconsistent ring sizes within a tx as a privacy red flag.

How does the four-tier fee model work?

monerod's get_fee_estimate returns four per-byte rates: slow / normal / fast / fastest. Wallets multiply by the tx weight to get the total fee. The mempool wall on the dashboard color-codes pending txs by which tier they fall into.

Why is there no address page?

Because Monero addresses can't be tracked from chain data alone. Outputs to an address are encrypted; only someone with the recipient's view key can scan the chain for them. The tx-detail page's "I received this tx" reveal flow is the legitimate path for a recipient who wants to see what landed at their address.

Why no Lightning, accelerator, or RBF?

None apply to Monero. Lightning is a Bitcoin L2 with no equivalent. There's no fee market accelerator on Monero. Replace-by-fee is a Bitcoin policy choice; Monero txs aren't mempool-replaceable in the same way.

What daemon do you talk to?

By default https://xmr-node.cakewallet.com:18081 — Cake Wallet's public node. Operators can point at any monerod via the MONEROD_RPC_URL environment variable.

How current is the data?

The backend polls the daemon every 3 seconds. New blocks and mempool deltas are pushed over WebSocket within ~5s of the daemon publishing them. Historical mempool stats are sampled at 1-minute intervals; on a fresh boot the chart fills over the first ~2 hours.

REST API

All endpoints under /api/v1/. JSON responses; no auth.

MethodPathReturns
GET/api/v1/infoheight, difficulty, hashrate, mempool count
GET/api/v1/blocks?count=Nlast N block headers (max 25)
GET/api/v1/block/:hashblock detail (header + tx hashes)
GET/api/v1/tx/:hashpublic tx fields (size, fee, ring info, RCT type, …)
GET/api/v1/mempoolfull mempool snapshot (sorted by fee)
GET/api/v1/fees/recommended4-tier fee model
GET/api/v1/statistics/2h (24h, 1w, 1m)mempool stats time series
GET/healthzliveness

Tx-detail responses NEVER include amounts, recipient addresses, or output one-time keys — RingCT-hidden by design.

WebSocket

ws://<host>/api/v1/ws — speaks the upstream mempool/mempool protocol so existing clients work. Send {"action":"init"} to get a snapshot, then receive pushes:

  • blocks on connect — recent block headers (oldest-first; client reverses)
  • block on every new tip
  • mempool-blocks on every mempool change
  • mempoolInfo, fees, vBytesPerSecond, transactions
  • projected-block-transactions when subscribed via {"track-mempool-block": 0}

Server-Sent Events

/api/v1/events — text/event-stream. Easier to consume than WebSocket if you only need read-only updates.

  • event: snapshot on connect — current info + mempool hashes
  • event: block on every new tip — full BlockHeader
  • event: mempool-delta — {added: [hashes], removed: [hashes]}

25-second comment heartbeats keep connections alive across proxy idle timeouts.

Privacy & limitations

  • Tx-detail reveal flows: keys never touch the server. Recipient (view key) and sender (tx_secret_key) decryption runs locally; only tx_proof verification crosses the wire, and tx_proof signatures are non-secret by design.
  • Fiat conversion: stub today. Real XMR/USD price feed is on the backlog; numbers in the fees-box are illustrative until then.
  • Mining-pool fingerprinting: stub (every block reads "unknown"). Parsing the coinbase extra field for known pool tags is a future iteration.
  • Ring decoy ages: the chain exposes raw delta-encoded global output indices on /tx/:hash. Resolving those to block heights via /get_outs for a "median decoy age" tooltip is on the backlog.
  • This explorer cannot tell you if you sent or received a tx unless you supply the keys. That's the whole point of Monero.
